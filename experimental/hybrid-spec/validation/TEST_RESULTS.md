| 指标 / 名称 | 本报告的口径 |
|---|---|
| 吞吐 tok/s | 客户端测量的输出 token / 时间；不是 prompt + output 合计 |
| mean TPOT | 官方流式客户端统计的平均输出 token 间耗时，单位 ms；并发下不能直接用 1000/总吞吐代替 |
| 吞吐提升 | `(方案吞吐 / 明确指定的基线吞吐 - 1) × 100%` |
| TPOT 变化 | `(方案 TPOT / 基线 TPOT - 1) × 100%`；负值表示降低 |
| SA fraction | 被选用 SA 候选的 decode 请求行占比；不是端到端请求命中率，也不是整批跳过率 |
| accept_length | 按各实验说明统计，通常含 bonus；服务累计指标、独立 probe 与计数器差分不能混为同一范围 |
| 实际验证 token / 行数 | target verify 实际执行行，包含 anchor 和 CUDA Graph padding，排除 prefill 与 neural draft forward |
| AR decode 行数 | 普通自回归的 target decode，**不是投机验证 token**；256 输出时首 token 来自 prefill，decode 为 255 行/请求 |
| native | 必须带算法、K 和模型；DSV4 的 native MTP 与 Qwen 的 native STANDALONE 不是同一路径 |
| full / split | full 保留完整 neural 起草；split 可跳过 SA 命中行的 neural 尾段 |
| 固定 compact | 最新测试为 SA8 / neural3 / gate1 + split + global pool + compact verify |
| 动态 compact | 在同一固定方案上增加在线反馈校准、动态长度与 Graph 档位选择；fixed 指 dynamic_verify=false，不等于 padded |

原生与固定 compact 的差异同时包含 SA、split、neural 长度上限和 target compact，**整体收益不能全部归因于 compact verify**。4090 大小模型对照未单独隔离 compact 的作用；新增 DSV4 c1 已有同名义 SA8/neural3 策略下的 padded/compact 对照，compact 观测更慢，但接受长度与来源比例也略有变化。

三次实验的配对收益按每次比值计算后求均值；两个均值的比值可能略有不同。单次补测引用上一轮第 3 次，不能混入三次均值。本地机器可读实验的百分比采用未四舍五入的结果计算；用户提供的 DSV4 汇总按其展示值核对，舍入与跨批次差异在专题中说明。

## 12. 已发现的问题与结果边界

| 问题 | 证据 / 处理 | 数据解释 |
|---|---|---|
| max_requests=1 后 SA 永久为零 | 新闸门按 len(states) 把 health/warmup 保留来源也算进容量；1→4 恢复，后续 lease 生命周期修复 | 不是 gate / TP 使查询失败；最初内网用 4 绕过 |
| 旧 split 预枚举 batch≤4 | 后续改 GPU 动态行号，并补齐 MTP/EAGLE3/STANDALONE | 历史报告的限制不是当前能力描述 |
| gate 大于 neural cap | 保留 gate 需要的前缀检查，verify 使用有效长度；gate3/neural2、gate8/neural1 已回归 | 不能简单截断 gate 或读不存在的 proposal |
| Qwen3.6 MTP experts 误继承 GPTQ | 独立 unquant 元数据修正加载，旧约 1.1 接受长度数据作废 | 加载修正收益不计作 SA 算法收益 |
| compact 初始化路径 | draft runner 绕过父构造器缺 ragged_verify_mode；能力检查早于 attention 初始化 | 已加入对应六项回归 |
| STANDALONE hidden-state merge/filter OOB | prefill hidden=None，draft-extend Graph 却生成 hidden；新旧 batch 合并后旧 hidden 行数不足 | Graph 使用 NULL capture，回放保留 None；其他 recurrent 路径保留 clone；所有正式 compact 臂应用同一补丁 |
| 空输出按请求上限计数 | 早期 sa-spec Python 客户端尝试曾误计空输出 | 被排除，改官方客户端并逐请求检查，不用于正式收益 |
| failed / interrupted profile | CPU-only trace、排空窗口、中断补测等 | 仅作诊断，未混入正式表 |

STANDALONE 修复旧源码负向对照为预期 2 失败 / 2 通过，修复后 4 通过；4060 最终 857 passed / 2 skipped。最新正式运行统一使用 c39 + 同一补丁，runtime SHA256=`af4de6504b29fe4276576259ab62db61362e378f0f17b2553ca93d51422fa157`。初版整理时该 runtime 与对应测试尚未提交；后续已有修复提交 `1a1dd4e567`。历史实验仍按 c39 + 当时补丁记录，**不要只拉 c39 就认为包含这份修复**。

当前证据支持的范围：

- DSV4 TP8 已有用户提供的 edits c1～32、离线表 fixed/dynamic compact 和 SWE c8/c16/c80 实测汇总；单次/900s 协议与内网产物路径已补齐，本次没有从新增目录逐请求复算，也没有新增质量验收。
- EAGLE3/MTP 三算法 split/compact 的组件覆盖与 STANDALONE 真实服务覆盖不同，不能互相替代。
- 真实大小模型 fixed 最快是这次工作负载和配置网格内的结果；原生 AR 的默认 overlap 等最优调优未搜索。
- 不以 SA 分组较高接受率证明同位置优于 neural；不以请求成功证明任务质量或输出恒等。
- 单卡 2/8 卡 skip 不能算多卡通过；用户后续 NCCL2/8 专项通过也不能替代最新完整模型 TP8 测试。
