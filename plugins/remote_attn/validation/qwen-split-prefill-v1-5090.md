# 分段 Prefill V1 的 RTX 5090 实测

实验日期为 2026-11-11 至 11-12。实验基线为
`codex/remote-pd-split-default@4f473e63aa`，各策略臂包含基线之上的实验改动。
表格来自 39 机的实测汇总。入库版本的协议与边界另由契约测试覆盖。

| 项目 | 设置 |

| 模型 | `Qwen/Qwen3.8-27B-FP8`，64 层（48 GDN + 16 full-attn），KV 64 KiB/token |

延迟单位为 ms，吞吐为输出 token/s。ITL 均值一列是逐请求计算
`(E2E − TTFT)/(输出 token 数 − 1)` 后取中位数。流式合批会让客户端的
`itl_mean` 包含零间隔，跨臂比较使用前一种口径。ITL p99 也先逐请求计算，
再取中位数。缺失指标以 `—` 标记。

## ITL 口径更正

2026-11-12 复核发现，早期表格里的 `ITL max` 是**逐请求最大 ITL 的中位数**。
当长停顿发生在少于一半的请求上时，这一列仍可能维持在 41–42 ms。
下文保留该统计量并标明中位数。评估停顿频率使用**打断率**，即逐请求最大 ITL
严格大于 100 ms 的请求占比。评估停顿时长时区分全体请求和受影响请求的分位数。

本次复核所列原生臂的打断率为 0%，32K 冷缓存原生臂的全体请求最大 ITL p90
为 41 ms。除另行标注外，下表的 split 数据使用原基准比例 0.70。
32K 热缓存的 E2E 变化以 `whole` 为基线，其余有对照的场景以原生 PD 为基线。

## 默认策略

P 以 `H = max(prefix_len, cache_protected_len)` 为命中长度，D 默认计算未命中
token 的 25%（cut 基准比例 0.75）。后缀至少为
`min(2048, max(N // 16, 1))`。有命中或 prompt
短于 32K 时，后缀还受 `min(chunk_cap, floor(0.15 × N))` 限制。
D 默认 chunk 为 4096，以 D 的 `--max-prefill-tokens` 为上限，声明的
`chunk_cap = max(实际 chunk, 2048)`。切点须越过实际命中前缀并落在双方
协商的范围内，否则走原生 PD。V3 offer 隔离采用固定后缀下限的旧端。

## 数据溯源与复现

- 39 机的原始数据位于 `/workspace/_p518v/splitp*/*.json`。目录 `splitp` 是早期批次，
  `splitpB` 是 cut 扫描，`splitpE` 是切分口径对照，`splitpF-G` 是斜率与回退，
  `splitpH-M` 覆盖 64K、C8 和后缀 cap，`splitpN-O` 覆盖 16K 和 72K。
- 早期 `TAG` 缺少 `SUFFIX` 和 `BASIS`。64K 和 32K C8 冷缓存的 cut 0.70 臂
  分别被钉后缀 16,384 和 4096 的 JSON 覆盖。cut 0.70 臂的 E2E 来自运行输出，
  这两个点需用唯一标签重跑后才能归档完整 JSON。
- 早期客户端缺少 ITL p99 和 max。后续客户端的流式合批会压低 `itl_mean`，
  因此表格使用本页开头的逐请求口径。
- 用每个 JSON 的 `records[].itl_max` 复核时，分别计算全体请求的中位数、p90、
  全局最大值和超过 100 ms 的占比。受影响请求的 p90 使用超过 100 ms 的子集计算。

以下命令使用 39 机已有实验脚本。脚本位置和输出目录沿用本次记录。

```bash
# <model> <arm> <mode> <concurrency> <total> <length> <hit> [cut]
SCHUNK=4096 bash /workspace/_p518v/splitp.sh hyb def all 4 80 32768 0
BASIS=whole SCHUNK=4096 bash /workspace/_p518v/splitp.sh hyb def all 4 40 32768 0.6
SUFFIX=4096 SCHUNK=4096 bash /workspace/_p518v/splitp.sh hyb def all 4 40 65408 0.4
```

分支中的参数说明见 [分段 Prefill](../QWEN38-HYBRID-D2D-ZH.md#分段-prefill)。
