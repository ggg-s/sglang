# RTX 4060 CUDA 验证

在 `ubuntu` SSH 配置指向的 WSL Linux 上验证，独立目录为
`/workspace/remote-attn-cuda-20261028`。没有修改已有项目或 Python 环境。

## 环境

- 单张 NVIDIA GeForce RTX 4060 Laptop GPU，约 8 GB 显存，SM 8.9。
- Python 3.12.3，PyTorch `2.13.0+cu130`，CUDA 13.0，FlashInfer `0.6.18`。
- `mooncake-transfer-engine-cuda13==0.3.13.post1`，`send_probe=True`。
- Mooncake 使用 TCP；源、目标分别运行在两个进程，共用这一张 GPU。
- 当前插件的实际 CUDA 拷贝、stream、Mooncake TE 和 FlashInfer 均未替换。
  scheduler/KV pool 使用小型 storage fixture，未加载模型。

## 通过的检查

1. FP16、BF16：调用插件的源端 attention、目标 tail attention 和 LSE merge，
   与完整序列的 FP32 PyTorch SDPA 参考比较。使用 257 tokens、193-token remote prefix、
   GQA（4 个 Q heads / 2 个 KV heads）及非连续源索引。
2. Fast async FP16：3 个源 buffer、2 条源 copy stream、1 个目标 slot，覆盖之前的 ACK 等待环。
3. Fast async BF16：2 个源 buffer、2 个目标 slots。
4. Fast sync FP16：单 buffer、单目标 slot。
5. Fast async FP16：目标使用完整 CPU mirror（slots=0）。
6. 普通 CPU snapshot BF16：逐层 Mooncake 传输，再异步 H2D。
7. 传输过程中取消：等待第一层，停止源传输并调用实际 target abort/fence，
   随后将 GPU 槽位写入新 owner 的 sentinel；确认没有后续 receiver 写入覆盖。

五组正常传输均使用 6 层、每层 2048 tokens、2 个 KV heads、head_dim=64，
检查所有 K/V 逐元素完全相等、目标映射前的 guard 区未改变，源/目标 live registration 都归零。
取消路径按预期保留未完成传输的目标 host registration，待该进程退出后回收；源端线程已退出并注销。

最终运行的最大绝对误差：FP16 为 `9.69e-5`，BF16 为 `9.25e-4`。
结束后 GPU 显存回到 `0 MiB`，验证进程已全部退出。

逐层 ready 时间、注册计数、源码 SHA256、依赖版本及数值误差见
[4060-results.json](4060-results.json)。

`--profile` 采集的目标进程 CUDA trace 中，H2D 与 GEMM 位于不同 stream，存在实际时间重合。
重合拷贝数和时长保存在结果首项的 `overlap` 字段。这是小张量的并行性验证，
不作为模型迁移加速比、全链路 Remote attention overlap 或吞吐收益的证据。
最终 trace 中有 12 次 H2D、315 个 GEMM kernel，其中 3 次 H2D 与 GEMM 重合，
累计约 `19.88 us`。首次运行也观察到重合，具体次数和时长受调度影响。

远端原始 trace 与日志分别保留在独立目录的 `results-final/overlap-trace.json`
和 `cuda-probe-final.log`；本机副本位于 `/private/tmp/remote-attn-cuda-4060-results/`。

## 复现

源码脚本：`test/manual/remote_attn/cuda_handoff_probe.py`。
在拥有上述依赖的环境，从 checkout 根目录执行：

```bash
PYTHONPATH=plugins/remote_attn python test/manual/remote_attn/cuda_handoff_probe.py \
  --output /tmp/remote-attn-cuda --profile
```

本机已有的编译器与 Python runtime 分开安装，因此本次使用：

```bash
cd /workspace/remote-attn-cuda-20261028
export CUDA_HOME=/workspace/conditional-graph-20261019/cuda13
export PATH="$CUDA_HOME/bin:/workspace/mixed-adapt-20261025/venv/bin:$PATH"
PYTHONPATH=plugins/remote_attn venv/bin/python \
  test/manual/remote_attn/cuda_handoff_probe.py --output results-final --profile
```

PyPI TLS 在远端失败，Mooncake wheel 由本机下载后上传并离线安装到独立 venv。
PyTorch/FlashInfer 依赖通过 `.pth` 复用已有环境。系统 `/usr/bin/nvcc` 为 CUDA 12.0，
不能编译当前 FlashInfer，必须选择上述 CUDA 13 工具链。
另修复 preflight 在加载 Mooncake 前先导入 PyTorch，避免 pip CUDA wheel 环境的
`libcudart.so.13` 动态库加载失败；尚未在这里运行完整 SGLang preflight/服务器启动。
