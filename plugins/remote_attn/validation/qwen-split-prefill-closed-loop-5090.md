# RTX 5090 Split Prefill 的 decode 时间预算实验

数据来自 RTX 5090 39 机。内网原型 `c47a35122a` 的数据采自 2026-11-15，
按拓扑对照自身基线。分支 `f974c5e311` 已复测 2P1D SWE-bench C=6，
并首次补测了 32K 的冷缓存和 90% 命中对照。

2P1D 原型的 g=0.2 使 TTFT p90 下降 16.7%，Mean TPOT 增加 22%。
原型 g=1.0 的 p90 降幅为 28.4%–37.9%，Mean TPOT 增加约 56%–60%。
这两档展示取舍，缺少中间点及重复结果来判断曲线和稳定性。
g=1.0 两次 TTFT p90 相差约 15%，因此不应单凭一次测量决定默认值。
历史 [固定 cap 4096](qwen-split-prefill-2p1d-5090.md) 使用了 600 s，
其 TTFT p90、TPOT、RPS 为 21,891 ms、18.56 ms、0.35，跨批次只能参考。

分支复测的 TTFT p90 为 20,376 ms，落在原型两次的 19,818–22,846 ms
区间内。对照基线，TTFT p50 下降 31.6%，p90 下降 36.2%，RPS 增加
9.7%，输出吞吐增加 30.3%。Mean TPOT 增加 81.5%，高于原型两轮。
这一轮日志记录 90 次 `selected` 和 1 次 `split_too_small`。
控制器本地 cap 从 4,096 升至 8,434，随后记录到 6,927–10,063；
δ 为 0.34–0.73，部分窗口高于 0.50 的目标。cap 的变化可能解释部分
TPOT 差异，仍需重复同配置才能判断差异是否稳定。

示例请求的实际 miss 为 49,209 token，按两边速率估算可搬约 23K，
最终受 cap 限制只搬 7,168，cut 为 49,593。这说明该请求的切点由

改变可承受的 cap。g=0.2 的记录显示准入比例已下降，δ 仍高于目标。

## 分支实现的口径

详见[分段 Prefill 配置](../QWEN38-HYBRID-D2D-ZH.md#分段-prefill)。
δ 是成功采样的 D 后缀和 decode forward 时间中的后缀占比。
只有在 decode 批形、每步成本和其他开销近似固定，且两类 forward 串行使用
同一执行资源时，`1/(1−δ)` 才近似描述 TPOT 膨胀。chunk 时间和等待轮次
都是估计值。分支保留原生回退、静态对照以及已有的自适应 cap 对照。
从 `f974c5e311` 起，D 按下一块实际 token 数限制等待预算，并使用 TP
准入投票后随请求保存的速率和步时。内网按整段 suffix 推导等待预算的
补丁 `7fd16f6a2f` 已作废。
